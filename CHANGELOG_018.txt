Update 018 — fast mobile recording finalization

Root cause fixed
----------------
The mobile recorder uploaded MediaRecorder chunks strictly one by one. A single slow PUT request
blocked every later chunk. After Stop, the UI waited for the entire serial Promise chain before it
could call /complete, so it could remain on “Сохраняем видео…” for a very long time.

Changes
-------
1. Up to 4 video chunks are uploaded concurrently while recording continues.
2. Every chunk has a fixed sequence number; the server accepts chunks out of order and idempotently.
3. Server stores chunks separately and assembles them in sequence only on /complete.
4. /complete receives the exact expected chunkCount and refuses to finalize if any chunk is missing.
5. Chunk requests have an explicit timeout and bounded retries; the UI can no longer wait forever.
6. Recorder target bitrate lowered to 1.8 Mbps and camera capture limited to max 1280 px per side.
7. Saving UI now shows a real percentage/progress bar instead of an indefinite spinner.
8. Android MP4/H.264/AAC recordings use ffprobe + FFmpeg stream-copy remux instead of full re-encode.
   Incompatible inputs still fall back to H.264/AAC normalization.
9. FFmpeg and FFprobe are both verified at application/deployment startup.
10. Mobile JS/CSS cache key advanced to v018.

No database migration is required.
No Bitrix24 reinstall is required.
Desktop Kontur.Talk workflow is unchanged.
