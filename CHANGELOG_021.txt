Update 021 — universal video sources, desktop screen recording, mobile file/link modes

1. Universal URL import
- Kontur.Talk URLs continue to use the existing authenticated KonturVideoDownloader.
- Other public HTTP/HTTPS URLs are handled automatically by yt-dlp; no source selector is required.
- Docker image installs pinned yt-dlp 2026.06.09 and Deno 2.8.1, plus existing FFmpeg/FFprobe.
- External URL imports disable playlists, cap download quality at 1080p, cap source size at 1 GiB by default, and normalize to the existing MP4 pipeline.
- Basic private/local-address protection is applied to the supplied URL.

2. Desktop source selector
- Three source modes: URL / Record / File.
- URL mode accepts Kontur.Talk and supported yt-dlp sites from one field.
- File mode accepts MP4, MOV, WebM, MKV and M4V up to 100 MiB.
- Removed the informational blue audio banner requested by the user.

3. Desktop screen capture
- Screen capture is moved into a separate same-origin top-level helper window. This avoids Bitrix Desktop iframe display-capture restrictions that prevented getDisplayMedia from opening the system chooser.
- Helper asks the browser for monitor capture, system audio and optional microphone.
- During screen recording the helper compacts into a small movable controller with REC timer and Stop.
- The web platform still requires the user to choose/confirm a screen surface for every capture session; the application cannot silently select the monitor.
- A browser popup cannot be guaranteed always-on-top or guaranteed excluded from full-monitor capture; this requires native integration.

4. Camera <-> screen switching during desktop recording
- Source buttons remain active while a recording session is running.
- Switching sources uses internal recording segments rather than mutating MediaRecorder tracks.
- The new source starts before the previous segment is stopped to avoid a visible gap.
- Ready segments are merged server-side into one MP4.
- Fast concat is used when codecs/resolution allow it; normalized FFmpeg concat is the fallback.

5. Upload pipeline/source metadata
- New mobile_video_upload.source_kind and declared_size_bytes fields via Flyway V5.
- Source kinds: RECORDING, FILE, MERGED.
- Manual file uploads are limited server-side to 100 MiB.
- New POST /bitrix/mobile/uploads/merge endpoint merges recording segments safely for the same signed Bitrix entity context.

6. Mobile Bitrix UI
- After CRM entity selection the user can choose: Link / Camera / File.
- Link mode uses the same automatic Kontur/yt-dlp URL pipeline as desktop.
- Camera keeps the existing mobile recording pipeline.
- File opens the Android/iOS file/gallery picker and accepts MP4/MOV/WebM/MKV/M4V up to 100 MiB.
- Screen capture is intentionally not exposed in the current Bitrix Android WebView because Android WebView does not expose getDisplayMedia; native MediaProjection integration would be required.

7. Validation performed in the development container
- node --check passed for desktop, mobile and screen-helper JavaScript.
- All JavaScript getElementById references were checked against their HTML templates: no missing IDs.
- New Java downloader/upload/merge classes were syntax-compiled with Java 21 using dependency stubs.
- MobileVideoMerger was functionally tested with real FFmpeg-generated H.264/AAC segments; fast concat produced a valid combined MP4.
- Full Maven build could not run in this assistant environment because Maven Central is unavailable here; the normal local/Docker build remains the final compile check.
