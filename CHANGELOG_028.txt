Update 028

Screen capture resilience and focus behavior

- Removed the explicit CaptureController focus-capturing-application request that kept the technical capture window in front after the system picker. The agent now asks for no-focus-change before getDisplayMedia binds the controller.
- Added durable handoff of each active screen segment upload id/token to the Bitrix widget.
- Added a watchdog that detects OS-close of the capture window even when beforeunload/postMessage is lost.
- Added POST /bitrix/mobile/uploads/{uploadId}/recover. It finalizes the contiguous chunks already stored on disk after an interrupted popup upload.
- Unexpected X-close no longer bricks the recorder: current screen recording is recovered and finalized; if camera is the current source, camera recording continues while prior screen segments recover in background.
- The widget remains reusable after interrupted screen capture.
- Cache-busting bumped to 028.

Important platform limitation

Bitrix Desktop 22.0.28.91 exposes no JavaScript-accessible native minimize/setResizable/Chrome App/Electron bridge in the tested build. A web page cannot programmatically press the OS title-bar minimize button without such a host/native API.
