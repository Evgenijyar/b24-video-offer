Update 029 — Bitrix CRM todo after view goal + editable client message
Date: 2026-08-11

Scope
- Screen-capture flow from 028 is intentionally unchanged.
- This update implements the two remaining Version 1.0 CRM workflow features requested for Video Offer.

1. CRM activity instead of a view timeline comment
- When the selected view goal is reached, the application no longer adds a separate "client viewed" timeline comment.
- The currently responsible employee is resolved from the current lead/deal/contact via crm.item.get -> assignedById.
- A universal CRM todo is created with crm.activity.todo.add and linked to the same CRM entity.
- ownerTypeId values: Lead=1, Deal=2, Contact=3.
- responsibleId is the entity's current assigned employee at the moment the goal is reached.
- deadline is the current date/time; pingOffsets=[0].
- Todo title examples:
  * "Связаться с клиентом — видео просмотрено: 1 минута"
  * "Связаться с клиентом — видео просмотрено: 50% видео"
  * "Связаться с клиентом — видео просмотрено: полный просмотр"
- The created activity ID is stored in video_offer.view_notification_activity_id.
- Existing retry/recovery logic for view notifications is retained and now retries CRM todo creation.

2. Editable "Сообщение для отправки"
- Added to both desktop and mobile Video Offer interfaces.
- Desktop: generated automatically when the Bitrix widget opens.
- Mobile: generated automatically after the manager selects a lead/deal/contact.
- The generated text is editable before offer creation.
- Base text is currently hard-coded intentionally for Version 1.0.
- The message contains a visible video-link placeholder while editing; the final public URL is substituted only after the offer is ready.
- The employee currently responsible for the CRM entity is resolved automatically.
- user.get is used to obtain available employee contact data:
  * PERSONAL_MOBILE
  * WORK_PHONE
  * PERSONAL_PHONE
  * EMAIL
- When a mobile number exists, separate WhatsApp, MAX and Telegram lines are generated with that number.
- Duplicate phone numbers are suppressed.
- The UI waits for the initial client-message template request before submitting an offer (10 s frontend safety timeout with fallback), preventing a fast click from silently losing the generated contacts.

3. Timeline message after offer readiness
- The previous generic timeline comment "Видео-оффер готов. Ссылка: ..." is replaced.
- After the video is READY, crm.timeline.comment.add receives the final edited client message with the real public URL substituted.
- If the user removes the URL placeholder while editing, the backend safely appends the public URL so a ready offer can never be published without its link.
- The exact edited message is persisted in video_offer.client_message before background processing, so asynchronous creation and retry preserve it.

4. Bitrix permission requirement
- crm.activity.todo.add and responsibleId resolution use the existing crm permission.
- Employee contact fields require Bitrix scope user_basic (or the broader user scope).
- If user_basic is not yet granted, the application remains functional and generates the base message without employee contacts; a precise warning is logged/client-reported.
- After user_basic is granted to the local application and Bitrix authorization is refreshed, contacts are populated automatically.

Database
- Added Flyway V7__client_message_and_view_activity.sql:
  * video_offer.client_message TEXT
  * video_offer.view_notification_activity_id BIGINT
- Legacy view_notification_comment_id is retained for backward compatibility with existing rows/schema.

Tests / validation added
- Added CRM system entity type ID assertions.
- Added client-message formatting test for manager name, phones, WhatsApp/MAX/Telegram, e-mail and duplicate-phone suppression.
- All active JavaScript files pass node --check.
- Desktop/mobile HTML element IDs were checked against JavaScript getElementById references.
- Modified core Java classes were selectively compiled with Java 21 against strict dependency stubs to validate syntax/signatures in this environment.
