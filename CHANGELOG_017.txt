Update 017 — mobile recorder reliability and UX

Root causes confirmed from the 2026-08-09 Android/BitrixMobile test log:
- recording itself was successful: MediaRecorder started as MP4/H.264/AAC and uploaded ~22.9 MB;
- completion succeeded, but server normalization failed because ffmpeg was not installed in the actually deployed image;
- the timer bug was client-side: startTimer() cleared recordingStartedAt before rendering;
- initial camera failure on the tested BitrixMobile WebView was reported as NotReadableError.

Changes:
1. Mobile recorder UI
   - compact one-row camera controls;
   - camera switch button;
   - one record button: red circle -> red square while recording;
   - Play/Pause button appears after successful save/normalization;
   - pressing Record again discards the previous unfinished/ready mobile upload and records a replacement;
   - removed technical chunk-upload explanation/progress text.

2. Recording timer
   - fixed deterministic 00:00 bug;
   - elapsed time now uses performance.now() and a separate timer, independent of MediaRecorder chunk timing;
   - timer updates every 250 ms and shows mm:ss.

3. Camera/microphone permissions
   - detects Permissions API state where the WebView exposes it;
   - handles NotAllowed/PermissionDenied/SecurityError;
   - on BitrixMobile Android also treats NotReadable/TrackStart as a possible host-app permission failure;
   - shows a dedicated permission modal;
   - provides best-effort Android intent button for Bitrix24 app settings plus manual fallback instructions;
   - automatically retries camera on visibility/focus/pageshow/resume after returning, without page reload when the WebView keeps the page alive.

4. FFmpeg deployment hardening
   - Docker runtime explicitly installs ffmpeg;
   - Docker build verifies command -v ffmpeg and ffmpeg -version;
   - MobileVideoTranscoder uses /usr/bin/ffmpeg by default;
   - application startup fails fast if ffmpeg is absent/not executable;
   - deploy.py verifies ffmpeg inside the running container before declaring deployment successful;
   - deploy health wait increased to ~120 seconds to avoid a false failure on slow starts.

5. Recording replacement cleanup
   - added DELETE /bitrix/mobile/uploads/{uploadId};
   - superseded/error mobile upload rows and files can be removed immediately instead of waiting for expiry cleanup.

No database migration is required. No application.properties changes are required.
Desktop Bitrix video-offer flow is untouched.
