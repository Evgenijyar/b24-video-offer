Update 026 — screen-capture agent UX refinement
Date: 2026-08-10
Base: Update 025

GOAL
- Keep the working top-level capture-agent architecture from Update 025 unchanged for actual capture/segment upload.
- Remove the visible helper UI and make the native Chromium source picker the only meaningful UI during screen selection.
- Center and tightly size the technical window around the native picker.
- Stop parking a tiny visible window in the lower-right corner after selection.

SELECTION WINDOW
- Removed the large visible “Выбрать экран” button completely.
- Capture agent HTML now has no visible controls, text, hints or status UI.
- Added a best-effort automatic getDisplayMedia() attempt immediately after agent INIT.
- Standards-compliant Chromium normally consumes the opener gesture in window.open(), so a newly-created popup may reject the automatic call with InvalidStateError. In that case the entire blank helper window becomes the single activation surface; any click inside it immediately opens the native picker. No visible button is rendered.
- The automatic InvalidStateError is not surfaced as a user-facing error in Bitrix. It is telemetry only.

WINDOW GEOMETRY
- The capture-agent outer window is explicitly resized to 612x614 px and centered on the active screen.
- These dimensions are derived from the supplied Windows/Bitrix Desktop screenshot: approximately 610x582 px native chooser client area plus the tested popup chrome.
- window.open also requests a 610x582 content area and centered left/top to minimize the initial resize flash.
- Removed all 16 px helper-page padding and all decorative UI, so there is no application-created margin around the native chooser.
- Added SCREEN_AGENT_WINDOW_GEOMETRY telemetry so actual outer/inner dimensions can be confirmed from the next production log.
- Suppressed the unnecessary /favicon.ico request with a data favicon.

AFTER “SHARE”
- Removed the old resizeTo(220, 90) and moveTo(bottom-right) parking behavior completely.
- If the runtime exposes Additional Windowing Controls AND window-management permission is already granted, the agent uses window.minimize() to genuinely minimize to the taskbar. The app never requests a new window-management permission just for this.
- Stable fallback: the agent becomes visually empty, blurs itself, and explicitly focuses window.opener.top (the actual Bitrix top-level window) rather than only focusing the embedded offer iframe. Repeated focus handoff is used to get the helper out of the foreground without moving or shrinking it.
- The helper stays alive because its document owns the display-capture source; closing it would stop sources tied to that global object. It still closes silently on the existing overall Stop/SHUTDOWN path.

FOCUS
- Uses CaptureController with focus-capturing-application when available, then hands foreground focus back to the top Bitrix window.

UNCHANGED
- Screen MediaStream ownership, system audio/microphone mixing, direct preview/WebRTC fallback, Camera <-> Screen switching, chunk uploads, segment ordering, merge and final Stop behavior remain the Update 025 implementation.

VALIDATION TARGETS
- JavaScript syntax check for all active project JS.
- Static HTML/JS element consistency.
- Patch application must reproduce full 026 tree from clean 025.
